## 单例服务启动参数

矩阵对每个 TP 和组别独立启动 `vllm serve`。以下以 TP2 为例；TP1/4/8 只更改 `ASCEND_RT_VISIBLE_DEVICES` 和 `--tensor-parallel-size`。脚本还设置 `PYTHONPATH` 为容器 `vllm-ascend` 与 `vllm` 源码目录、`VLLM_PLUGINS=ascend`、`VLLM_USE_V2_MODEL_RUNNER=1`，并把自定义 OPP 目录加入 `ASCEND_CUSTOM_OPP_PATH`。实际执行的完整命令也逐例保存在 `metadata.json`。

```bash
export ASCEND_RT_VISIBLE_DEVICES=0,1
export PYTHONPATH=/home/w00664509/dspark-vllm/hardware-vllm-ascend/vllm-ascend-spec1-20261013:/home/w00664509/dspark-vllm/vllm-ced6857${PYTHONPATH:+:$PYTHONPATH}
export VLLM_PLUGINS=ascend
export VLLM_USE_V2_MODEL_RUNNER=1
export ASCEND_CUSTOM_OPP_PATH=/home/w00664509/dspark-vllm/hardware-vllm-ascend/vllm-ascend-spec1-sync-20260915/vllm_ascend/_cann_ops_custom/vendors/custom_transformer${ASCEND_CUSTOM_OPP_PATH:+:$ASCEND_CUSTOM_OPP_PATH}

vllm serve /home/vllm/weights/Qwen3-4B/ \
  --host 0.0.0.0 --port 8006 --max-model-len 256 \
  --served-model-name auto --gpu-memory-utilization 0.86 \
  --tensor-parallel-size 2 --max-num-seqs 16 \
  --async-scheduling \
  --compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY"}' \
  --safetensors-load-strategy prefetch
```

`target` 使用上述命令。`adaptive` 在末尾追加：

```bash
--speculative-config '{"method":"dspark","model":"/home/vllm/weights/Qwen3-4b-dspark","num_speculative_tokens":5,"enable_adaptive_verification":true}'
```

`physical` 再追加：

```bash
--additional-config '{"dynamic_spec_config":{"method":"dspark","physical_k":{}}}'
```

## 压测、精度与汇总

脚本对 `http://127.0.0.1:8006/v1/completions` 使用 `vllm bench serve --backend openai --model auto --dataset-name random --random-input-len 128 --random-output-len 128 --max-concurrency 16 --request-rate inf --ignore-eos --seed 20261013`，先预热，再正式测量。每例的原始产物位于 `tpN/<case>/`：`metadata.json`、`server.log`、`accuracy.json`、`warmup.json`/`.log` 和 `benchmark-1..3.json`/`.log`。

矩阵全部通过后，用以下命令生成 `summary.json`、`summary.csv` 与 `accuracy-summary.json`：

```bash
python3 experiments/dspark_tp/summarize.py \
  --current-root /home/w00664509/dspark-vllm/dspark_tp_results/retest-20261014-spec1 \
  --output-dir /home/w00664509/dspark-vllm/dspark_tp_results/retest-20261014-spec1/summary \
  --cases target adaptive physical --tps 1 2 4 8
```

同 TP 逐条比对 `accuracy.json` 的文本。优先检查 `physical` 与 `adaptive` 是否完全一致；`target` 与投机组若分叉，还需用修改前的 `new` 分支对照，区分投机解码原有数值差异与本次实现的回归。要判断代码是否影响不开 DSpark / 仅开置信头的性能，也必须在同机、同卡、同负载下对 `new` 与 `spec1` 两个源码版本分别重启服务测试，按相邻配对比较；历史非配对数字不能单独证明“无影响”。
