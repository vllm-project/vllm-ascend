# AttnResFwd

## 当前统一 N 轴并行方案

本轮以正式 PR 的 `c730f7177` 为优化前对照。
BF16、H7168、B1/4/8/16、N1到8的目标混合用例全部使用新 kernel 沿候选行并行打分，
不再回退到旧 kernel 或单 worker token 打分。核组大小由候选行数、可用核数和 UB 预算计算；
输出仍由每个 token 的一个核处理完整 H，并保留一次就绪同步。

Token 核组路径中，输出 owner 的自身分数保留在 UB，只读取其他 worker 的分数；prefix 写回与打分重叠，
在就绪同步前保证写回完成。A2 另在融合加法时重叠读取 addend，省去一次中间 BF16 拷贝。
未改变计算顺序或两处 BF16 舍入边界。A2 小 N 相对正式 PR 仍有性能退化，继续保留新路径优化。
历史测量描述其对应冻结版本；最新四轮复测见本文末尾，不混用不同版本的性能数据。

## 功能说明

`AttnResFwd` 是 Kimi K3 的注意力残差融合算子。单个 Torch 入口
`torch.ops._C_ascend.attn_res_fwd` 将可选的 BF16 加法、残差 bank 混合、
可选的输出 RMSNorm，以及 bank 写回放在一次调用中。源码注册覆盖
A2、A3 和 A5，小 batch 协作路径同时接入三类平台。已在 Ascend910B3 和
Ascend950PR_9579 上完成本仓库源码的原生构建、安装及完整算子精度验证，
包含大 H 分段用例。A5 使用独立 RegBase 协作实现；A3 仍需对应硬件验证。

令 `p` 为 `prefix_sum`（有 `addend` 时先做 BF16 加法），`v_i` 为
`block_residual` 中前 `num_valid_blocks` 行，并令最后一行 `v_N=p`。
启用 `mix` 时，每行先按 `norm_eps` 做 RMSNorm，再与 `norm_weight`、
`proj_weight` 相乘并沿隐藏维求和，所得分数经 softmax 后对原始 `v_i`
加权求和并舍入到 BF16。`mix=False` 时直接使用 `p`。传入
`output_norm_weight` 时，对混合结果再做一次 RMSNorm。

## 接口与参数

```python
output, raw_prefix, materialized = torch.ops._C_ascend.attn_res_fwd(
    prefix_sum, addend, block_residual, proj_weight, norm_weight,
    norm_eps, num_valid_blocks, output_norm_weight=None,
    output_norm_eps=1e-5, block_write_idx=-1,
    return_materialized=False, mix=True, optimize_prefill=False,
)
```

| 参数 | 形状与约束 | 作用 |
| --- | --- | --- |
| `prefix_sum` | `[T,H]`，BF16，连续 | 当前层的残差前缀。 |
| `addend` | `None` 或 `[T,H]`，BF16，连续 | 可选的前层输出；加法结果以 BF16 供后续计算。 |
| `block_residual` | `[T,S,H]`，BF16；每行连续，token 间可有 stride | 残差 bank；仅前 `num_valid_blocks` 行参与混合。 |
| `proj_weight`、`norm_weight` | 分别为 `[1,H]`、`[H]`，BF16，连续 | 混合分数的投影和 RMSNorm 权重。 |
| `norm_eps`、`num_valid_blocks` | `norm_eps` 为 FP32 可表示的有限正数；`0 ≤ num_valid_blocks ≤ S` | 混合归一化参数和有效 bank 行数。 |
| `output_norm_weight`、`output_norm_eps` | `None` 或 `[H]`，BF16，连续；传入权重时 epsilon 为 FP32 可表示的有限正数 | 可选的输出 RMSNorm。 |
| `block_write_idx` | `-1` 或 `[num_valid_blocks,S)` 中的行号 | 将 `raw_prefix` 写入尚未参与本次混合的 bank 行；`-1` 表示不写回。 |
| `return_materialized` | `bool` | 为真时单独保留归一化前的混合结果。 |
| `mix` | `bool` | 为假时跳过 bank 混合，用于前层或只做加法的路径。 |
| `optimize_prefill` | `bool` | 请求 prefill 策略；满足输出归一化、每核多 token 和 UB 容量条件时复用缓存权重。 |

所有 Tensor 必须位于同一设备。`output`、`raw_prefix` 和
`materialized` 均为 `[T,H]`、BF16。无 `addend` 时 `raw_prefix`
复用输入 `prefix_sum`；`return_materialized=False` 时
`materialized` 复用 `output`。写回只修改指定的 bank 行，不修改
`prefix_sum` 或 `addend`。`T=0` 可走空输出路径。
启用 bank 写回时，`block_residual` 不得与其他只读输入共享存储；Torch 入口会在
提交 kernel 前拒绝这类别名。关闭写回时仍允许只读输入共享 bank 存储。
底层 ACLNN 调用方同样需要保证写回 bank 与其他输入不重叠。

## 分核与数据复用

令 token 数为 T、有效历史行数为 N、候选行数为 R=N+1、可用 AIV 核数为 C。
每次调用只启动一个 kernel。完整 H 能否驻留由 UB 容量决定，不以7168作为硬编码边界。

### 全局行并行（40030）

1. 将 T*R 个完整 H 打分任务按核号步进分发，启动 `min(C,T*R)` 个核。
   每行计算 RMSNorm 与投影点积，在独占的32字节 workspace 槽写一个 score。
2. 所有启动核执行一次 `SyncAll<true>()`，等待分数与融合 prefix 就绪。
3. 启动核数为 U 时，token t 的输出核为 `floor(t*U/T)`，每个 token 有唯一输出核。
   该核对 R 个 score 做 softmax，读取原始候选行并对完整 H 加权累加。
4. 混合结果先舍入 BF16，再由该核完成可选的输出 RMSNorm，无第二次核间同步。

打分先处理 prefix，score 存储仍为历史行在前、prefix 在后。无任务循环覆盖时，
输出 owner 可复用驻留的 BF16 prefix；其余情况重新读取，避免使用已覆盖的中间量。

### Token 核组（40040）

完整行满足 UB 预算且 `T>C/4` 时，Host 按候选行数和可用核数计算均匀 token 核组：
`Gmax=min(R,C/T)`、`W=ceil(R/Gmax)`、`G=ceil(R/W)`，使用 `T*G` 个打分核。
它保留最大均匀核组的关键打分波数，并减少没有缩短关键路径的多余 worker。
低 token 占用保留全局行调度或既有的多 worker 核组；目标矩阵不回退到单核 token 打分。
核号 `core/groupSize` 确定 token，`core%groupSize` 确定组内位置。
leader 保留原始 BF16 prefix，并按 UB 余量缓存本核负责的历史候选行。

- 多 worker 组各自打分，leader 的自身分数保留在 UB，其他 worker 写独占 score 槽。
  全体 AIV 执行一次就绪同步，leader 只读取远端分数，再完成 softmax、完整 H 加权和输出 RMSNorm。
- 本轮高 token 占用的完整行方案直接采用多 worker 核组，不再使用先前的收益准入门槛。
  没有具体 B/N 白名单；不满足协作框架条件的其他场景仍保留原路径。

A5 的 UB 预算计入实际分配：直接从 `rowBf16_` 搬出，不分配输出队列；
核组均分配 GM 分数队列，余量用于缓存更多 BF16 候选行。
核组 leader 按 UB 余量缓存候选行，输出仍由一个 owner 完成完整 H。
当前 Host 不发射 `groupSize=1` 的40040，旧单 worker 对照分支及其专用累加 helper 已删除。
目标矩阵之外的老 kernel 仍采用单核 token 模式，相关历史优化见本文末尾。

完整行结果在 `V_MTE3` 事件后直接 `DataCopyPad` 写 GM，等待 `MTE3_V` 再复用。
A2/A3 另有 UB 地址 padding、循环外 Counter mask、BF16 多 repeat Copy 和归约尾块初始化；
这些调优不直接套用到 A5。A5 使用独立 RegBase 算术与归约实现。

### 大 H 与其他路径

协作框架要求 T 不超过 C/2、H 至少512、R 在2到128之间，并由 Host 核对 UB 预算。
完整行放不下时保留 H 分段：先归并平方和求整行 invRms，再归并分段 score，
输出按 H 分段；启用输出 RMSNorm 时还要归并输出平方和。这需要额外同步，
不承诺一次 SyncAll。超过所有支持的分段预算时明确报错。
不满足协作框架条件的其他 shape、非混合及 prefill 路径保留对应实现。
当前 B=1/4/8/16、N=1到8、H=7168 的目标选路如下：

| 平台 | B=1/4/8，N=1到8 | B=16，N=1到8 |
| --- | --- | --- |
| A2 | 新 kernel，N 行并行或多 worker token 核组 | G=2，共32个打分核 |
| A5 | 新 kernel，N 行并行或多 worker token 核组 | N1/3为G=2，其余为G=3，共32/48个打分核 |

Host 通过 `ShouldUseCooperativeKernel` 控制准入，仅接受非空且 `tokenGroupSize!=1` 的计划。
生产代码没有 B/N 白名单；上表是该通用规则在目标矩阵中的结果。
目标矩阵之外的老 kernel 仍根据 UB 容量选择 RESIDENT 或 RELOAD，不强制指定某个旧 tiling key。
此前 `T*(R-W) > 2*(P-T)` 的保守代理不再控制上述高占用完整行核组。
完整行不满足 UB 预算时仍走 H 分段。

## 校验与测试

Torch、ACLNN 和 Tiling 检查 BF16 dtype、形状、stride、epsilon、整数溢出和 bank 写槽。
投影严格为 `[1,H]`，epsilon 须为 FP32 可表示的有限正数；写槽不得覆盖有效历史行。
空 token 同样先校验元数据与 dtype。Torch 拒绝写回 bank 与只读输入共享存储。
原生 ACLNN 调用方也须保证可写 bank 不与其他输入重叠。

- NPU：`tests/e2e/nightly/single_node/ops/singlecard_ops/test_attn_res_fwd.py`
  和同目录 `test_attn_res_fwd_cooperative.py`。
- 上述 `41e163a30` 版本在 A2/A5 各通过153条 NPU 用例；含四条大 H、完整驻留尾块边界、
  可选加法/归一化/materialized、带 stride 的 bank、写回和非法 FP16/FP32/INT32 拒绝。
