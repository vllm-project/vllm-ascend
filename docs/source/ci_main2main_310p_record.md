# 310P 主干回归 (main2main) 运行记录与维护文档

## 1. 验证环境
- **硬件**: Atlas 310P (双芯, 44GB HBM)
- **软件**: CANN 9.1.0, vLLM 0.26.0, torch_npu 2.10.0
- **验证时间**: 2026年11月12日

## 2. 最小复现与回归验证记录
针对 310P 上的偶发失败（Flaky），设计了独立的 `test_flaky_repro_310p.py` 用例。
该用例强制限制显存利用率 (`gpu_memory_utilization=0.8`)，开启 `enforce_eager`，并设置了 600s 的超时和 1 次自动重试。

### 本地运行结果：
- 测试结果：**1 passed**
- 总耗时：**506.15s (0:08:26)**
- 分析：其中模型权重下载耗时 432 秒，实际引擎初始化与推理仅耗时约 70 秒。证明了 600s 的超时边界既能容忍网络波动，又能有效捕获底层死锁。

## 3. 维护说明
- 310P CI 的 E2E 用例必须使用 `float16` 精度，且禁止开启图模式。
- 遇到 Flaky 时，优先查看测试用例内部是否抛出 OOM 或超时异常。
- 主干回归采用分组解耦策略，`_310p` 下的用例失败不会阻塞 A2/A3 的常规校验。
- 通过设置 `VLLM_WORKER_MULTIPROC_METHOD="spawn"`，彻底解决了 pytest 环境下 fork 子进程导致的死锁挂起问题。
