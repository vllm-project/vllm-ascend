# GitCode 外部写操作通用授权边界

GitCode 评论、Issue 更新、push、PR 和 CI 触发会改变本地历史或远端状态。toolkit 只定义
所有调用方都适用的最小授权边界，不定义具体业务的批次、Issue 清单或聚合执行模型。

## 写前精确确认

每项写操作必须能追溯到当前会话中对以下信息的明确确认：

- 精确目标，例如仓库、Issue/PR、remote 和分支；
- 将要写入的完整内容，例如评论正文、PR 标题与正文或 commit SHA；
- 操作类型，例如 POST、PATCH、push 或 CI 触发；
- 对高风险操作额外展示的影响，例如共享/保护分支和非快进结果。

调用方名称、宽泛任务描述、Token 可用、配置文件或运行平台的工具审批都不能替代该确认。
没有合法确认时停在写操作前，保留已经完成的只读分析和本地结果。

## 证据与失效

调用方可以把确认结果作为检查点证据传给共享子流程，但证据至少应绑定目标、操作类型和
内容摘要。共享子流程只校验调用方传入的证据是否覆盖当前准确操作，不推断业务作用域。

出现以下任一变化时，未执行操作的原证据失效：

- 仓库、Issue/PR、remote 或目标分支变化；
- 评论、PR 正文、commit、推送 SHA 等内容实质变化；
- 新增了确认预览中没有的写操作；
- 当前会话无法提供原检查点证据。

证据有效时，同一准确操作不应因为进入另一个 reference 或共享脚本而重复询问。

## 写后回查

用户确认只授权执行，不能替代结果验证：

- API POST/PATCH 后使用 GET 回查目标字段和内容；
- push 后使用 `git ls-remote` 等只读命令核对远端 SHA；
- 状态码成功但响应字段缺失、目标不匹配或回查失败时，不得标记完成；
- 结果未知时先执行只读回查，再决定是否重试非幂等写入。

用户拒绝或缩小授权时，只停止超出范围的写操作，不扩大目标、不更换交付路径，也不丢弃
已完成的本地分析和验证结果。
