# 报告过滤（超长报告精简）

## 触发条件

主 Agent 在阶段3 生成报告后，执行 `wc -l {报告路径}` 检查行数。若 >5000 行，派发本子 Agent 执行过滤。≤5000 行则跳过，正常结束。

## 派发

```
Agent({
  subagent_type: "general",
  description: "超长报告过滤",
  prompt: "超长检视报告过滤

【输入】
- 报告文件路径：{report_path}

【任务】
读取报告 md 文件，对「发现问题（HIGH 置信度）」「需关注（MED 置信度）」「疑似（LOW 置信度）」三个章节中的检视发现做过滤，去除不严重的条目以缩短报告长度。

【过滤范围】
- 仅过滤上述三个章节的检视发现条目
- 「设计一致性检查」章节不动
- 「代码风格」章节不动
- 「检视概览」「检视统计」章节不动（但统计数字需在过滤后更新，见下方）
- 「范围外备注」章节不动

【过滤原则】

1. **禁止按条例ID合并去重**：同一个条例在不同代码片段上触发是正常的，每个触发点都是独立的检视意见，不得因为条例ID相同就合并或去除

2. **按问题严重程度判断**：MED 和 LOW 都按严重程度判断，不搞「LOW 默认去掉」。判断维度：
   - **保留**（严重）：涉及内存安全、数值溢出/下溢、数组越界、指针未初始化、外部输入未校验、GM 越界读写、除零、空指针解引用、资源泄漏、SIMT 红线违规等
   - **可去除**（不严重）：纯命名规范、日志措辞/语法、代码风格性意见、注释缺失、行宽超限等

3. **HIGH 置信度倾向保留**：HIGH 条目通常证据充分，优先保留。仅在明显不严重（如纯风格性）且报告极度超长时考虑去除

【过滤后必做】

1. **更新检视统计表**：过滤后「检视统计」章节的 PASS/FAIL/SUSPICIOUS 数字可能与原值不同（去除的条目不再计入），更新为过滤后的实际数字和占比
2. **覆盖原文件**：将过滤后的完整报告写回 {report_path}，原地覆盖
3. **不留过滤痕迹**：不得在报告中添加任何关于过滤的说明、标注、摘要行——用户不应感知过滤过程

【输出】
完成后仅返回：「已完成，过滤前 {N} 行 → 过滤后 {M} 行，去除 {K} 个条目」。禁止返回报告内容本身。"
})
```

## 约束

- 本 step 为派发子 Agent 执行，主 Agent 仅负责检查行数和派发
- 过滤结果覆盖原报告文件，不另存
- 子 Agent 不返回报告内容，仅返回行数摘要
