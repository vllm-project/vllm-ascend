# 检视负载均衡配置

> **本文件是检视负载均衡的规则定义处。** 每波子 Agent 上限、跨文档合并规则、专项文件处理在此定义。每个 reference 文件的「每组派发多少条款」由该文件 `<检视负载>` 头的 `通用检视子 agent 检视条款容量上限` 字段自声明，不在此硬编码文件清单。`steps/common.plan-design.md`、`steps/pr-large-review.clause-grouping.md`、`agents/ascendc-ops-reviewer.md` 引用本文件。

## 每组条款容量：文件自声明

每个 reference 文件在 `<检视负载>` 头声明 `通用检视子 agent 检视条款容量上限: N`，表示一个通用检视子 agent 一次检视该文件条款的推荐上限。计划设计子 agent 扫描 `<检视负载>` 头时一并读取该字段，按其打包每组条款。

- 容量值越小 → 条款检视负载越重（需仔细审，少打包）
- 容量值越大 → 条款模式化，可批量处理
- `<检视负载>` 头内容为「此条款文档由专项检视子 agent 独立托管，不参与条款派发流程」→ 不进通用检视波次，走专项处理（见下）

调整某文件的每组容量，只改该文件的 `<检视负载>` 头字段，无需改本文件。

## 跨文档合并取最小值

`plan-design` 的跨文档同类合并可能把不同文件的条款合到同组。合并后每组容量取组内各条款所属文件容量的**最小值**（就高不就低——含重负载条款的组整体少打包）。

示例：cpp-secure（容量 10）与 ascendc-topk（容量 3）的数值安全条款合并 → 合并组容量取 min(10,3)=3。

## 专项文件处理

`<检视负载>` 头声明「此条款文档由专项检视子 agent 独立托管，不参与条款派发流程」的文件不进通用检视波次：

| 文件 | 处理方式 | 理由 |
|------|---------|------|
| `cpp-style.md` | 全部条例单独成 1 组，并入第一波，`[STYLE]` 标记，不走假设检验 | 专项检视子 agent，违反即 FAIL，不进 PASS/FAIL 统计 |
| `doc-style.md` | D8 文档格式检视专用，由专项检视子 agent（design-check）按需读取 | 不走假设检验，独立于条例检视 |

无 `<适用>` 头的辅助文件（如 `simt-constraints.md`）非独立检视文件，检视对应主文件时作为参考补充读取。

## 每波子 Agent 上限

**≤6 个通用检视子 agent/波**（波内并行，波间串行）。专项检视子 agent（design-check）的派发时机见各 workflow。

降低并发度的同时靠每组多打包条款维持总吞吐。

## 波次排序

大型 PR 的负载感知波次构建只用 priority（高危优先）排序，同 priority 内按文件数+条款数粗排。不再使用 estimated_load 加权——容量已在分组阶段体现（容量小的文件少打包），波次排序无需重复加权。
